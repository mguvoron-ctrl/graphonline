Модернизация GraphOnline

Работа идёт небольшими проверяемыми изменениями. Существующие переводы, Canvas, алгоритмические расширения и старые XML-документы сохраняются. Новые изолированные части пишутся на TypeScript; PHP обновляется до 8.4. Перевод всего проекта на другой серверный язык не нужен для уже выявленных проблем.

В текущем изменении реализованы:

- TypeScript-модули истории, IndexedDB, GraphML, runner и временной шкалы. Они подключены через адаптеры к существующему JS.
- Воспроизводимая сборка из исходников, lockfile, автоматические проверки и CI. JS больше не компилируется через административную HTTP-страницу или при обычном запросе PHP.
- Локальный запуск на Mac через установленный PHP без Docker и Node; двойной клик запускает редактор, отдельная команда останавливает только сервер этой папки. Docker доступен как дополнительный вариант.
- Проверка XML, размера и структуры графа; HTTP-ошибки; атомарная публикация неизменяемых снимков. Чтение ссылки не позволяет изменять опубликованный граф. Повторная публикация создаёт новый адрес; старый остаётся доступен.
- Защита подтверждённых путей XSS, проверка SVG, ограничения PNG, закрытие служебных операций для публичного HTTP. Админка по умолчанию отключена; после настройки использует серверные сессии и CSRF-токены вместо MD5 в cookie.
- Загрузка основных страниц и API на PHP 8.4. Старые компоненты ExtraPacker исключены из обычного пути исполнения.
- Локальное автосохранение без зависимости от cookie и CompressionStream, восстановление после перезагрузки, понятные состояния ошибок сохранения.
- Координатор версий автосохранения: чистый документ не сериализуется при действиях с камерой, старые записи не скрывают новые изменения, сохраняется и ссылка документа. Прямые изменения старых расширений страхуются проверкой раз в 10 секунд.
- Объединение перерисовок через requestAnimationFrame, синхронный кадр для PNG, один таймер анимации пути. Исправлены направление wheel/pinch, согласование CSS-пикселей с буфером Retina и сброс камеры после раскладки. Решения и ограничения описаны в [rendering.md](rendering.md).
- Постоянный широкий редактор, заданный серверным шаблоном до запуска JS; узкий вид удалён. Fullscreen API дополнительно скрывает панели браузера, а выход через Esc сохраняет широкий вид. Верхние панели можно свернуть и вернуть кнопкой на поле, сохранив параметры, алгоритм и камеру. Инструменты и диалоги остаются доступны; размер Canvas учитывает изменение высоты панелей и статусов.
- Undo/Redo до 100 состояний с общим бюджетом 16 МиБ оценочного размера XML-снимков, горячие клавиши Ctrl/Cmd+Z и Shift+Ctrl/Cmd+Z. Большие документы сохраняют меньше состояний; это ограничение содержимого истории, а не всего JS heap. Импорт отменяем; восстановление истории имеет общий путь реализации.
- Чтение стандартного GraphML и старого формата. Внешние текстовые ID нормализуются для числового ABI GraphOffline; подписи сохраняются. Собственные ID остаются стабильны при повторной загрузке. Стандартный экспорт сохраняет оформление в явно названных GraphML extension keys.
- Исправления максимальной степени, отображения большого потока, недостижимости/диагонали/отрицательных циклов Флойда, восстановления подписей после просмотра Флойда, проверки чисел матриц и лимита вершин.
- GraphOffline в Worker на desktop/mobile, отмена и тайм-аут, защита от результатов старого запуска. Свободный worker повторно используется при переключении инструментов; выполняющийся запрос по-прежнему отменяется. CGI больше не нужен основному браузерному сценарию.
- Управление шагами BFS/DFS: назад/вперёд, воспроизведение, пауза и скорость. Подготовка использует индекс соседей и компактный журнал посещений вместо копий всего пройденного пути на каждом шаге. Временные подписи анализа не попадают в сохраняемый документ.
- Индекс рёбер для построения числовой и текстовой матриц смежности; Флойд использует тот же путь инициализации. Индекс создаётся на время операции, поэтому прямые изменения старых плагинов не оставляют устаревший кэш. Измерения и оставшиеся ограничения описаны в [performance.md](performance.md).
- Автораскладка выделена в чистый TypeScript-модуль и отдельный Worker. Вместо временных Point на каждой итерации используются числовые буферы и списки соседей. Круговое расположение видно сразу; есть прогресс, остановка и тайм-аут. Новая кнопка «Расположить вершины» сохраняет одну операцию Undo/Redo. Старые результаты не применяются после изменения геометрии, замены документа или обычного редактирования; при частичной раскладке существующие вершины закреплены. Каждый Application теперь владеет своей моделью графа вместо общего экземпляра в прототипе.
- PNG/SVG скачиваются из браузера без серверной обработки и загрузки изображения на сервер.
- Офлайн-кэш публичной оболочки, локальных ресурсов и WASM; сохранённый локальный граф и вычисления доступны после повторного открытия без сети. Backend и административные страницы не кэшируются.

Проверки находятся в `tests/unit` и `tests/browser`. Они проверяют правильные результаты, сохранность документа, отказы, инъекции, desktop/mobile, отмену вычислений, локальное восстановление и офлайн-запуск. Это регрессионный набор для изменяемых сценариев, а не доказательство корректности всех существующих алгоритмов.

Дальнейшие этапы:

1. Продолжить выделение чистой модели GraphDocument из Graph/Application, ввести централизованные команды изменений. Текущие версии автосохранения пока не заменяют этот контракт для всех расширений. Распространить индексы на остальные поиски вершин и рёбер; после централизации изменений безопасно переиспользовать их между операциями. Заменить сохранение снимков истории командами там, где измерения покажут пользу.
2. Измерить пользу приближённого расчёта сил для больших графов; попарное отталкивание раскладки пока O(V²). Перенести оставшиеся тяжёлые JS-алгоритмы с UI-потока; добавить сравнение с независимыми реализациями для всех точных алгоритмов.
3. Добавить таблицы очереди/стека и расстояний к учебному режиму; расширить шаги на Дейкстру и Беллмана–Форда. Для этого нужен журнал событий движка или отдельная проверяемая учебная реализация.
4. Добавить панель свойств, полноценный список локальных документов и обработку конфликтов нескольких вкладок. Проверить основные сценарии экранным диктором и на реальных сенсорных устройствах.
5. Обновить старые jQuery/jQuery UI, CKEditor и PmWiki отдельными миграциями с проверкой контента и совместимости. Wiki и административное редактирование контента не прошли полный перенос на PHP 8.4 в этом изменении.
6. Довести новые тексты интерфейса до всех 14 языков, проверить Safari/Firefox и внешние инструменты GraphML. Сейчас новые элементы переведены на русский и английский; остальные языки получают английский fallback.

Текущая работа не публикует сайт, не меняет production и не выполняет операций удаления пользовательских графов. Миграция схемы допускает чтение старых документов; для проверки на production нужна отдельная резервная копия и проверка эксплуатационной конфигурации.
