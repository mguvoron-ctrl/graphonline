Запуск GraphOnline на Mac без Docker

Если вы не знаете, что установлено:

1. Распакуйте архив целиком.
2. Откройте `Install PHP.command` двойным кликом. Он проверит PHP и при необходимости запустит официальный установщик Homebrew, затем установит PHP и откроет редактор. Если всё уже есть, установка пропускается.
3. Для последующих запусков открывайте `Start GraphOnline.command`, для остановки — `Stop GraphOnline.command`.

Во время первой установки Homebrew может попросить нажать Enter и ввести пароль входа в Mac. При вводе пароля символы не появляются — это обычное поведение Терминала. Первая установка может занять время, особенно если нужны инструменты Apple Command Line Tools; постоянный Docker-сервис и образы не требуются.

Если macOS не даёт открыть `.command`, откройте Терминал через поиск Spotlight (`⌘ + пробел`, введите «Терминал»). Введите `cd ` с пробелом, перетащите распакованную папку в окно и нажмите Enter. Затем выполните `bash tools/install-macos.sh`. Отключать защиту macOS не нужно.

Для тех, у кого Homebrew или PHP уже настроены:

1. Нужен PHP 8.4 или новее с расширениями DOM и zlib. Если Homebrew уже установлен, выполните один раз:

   ```sh
   brew install php@8.4
   ```

   Скрипт сам находит PHP 8.4 в стандартных каталогах Homebrew на Apple Silicon и Intel; `brew link --force` не нужен. Если Homebrew ещё нет, установите его по инструкции на [brew.sh](https://brew.sh), затем PHP. Первая установка загрузит PHP и его зависимости; последующие запуски ничего не устанавливают.
2. Распакуйте архив целиком в обычную папку. Либо скачайте ветку `codex/graphonline-modernization` репозитория `mguvoron-ctrl/graphonline`: изменения уже опубликованы именно в ней.
3. Откройте `Start GraphOnline.command`. Файл запустит PHP непосредственно на Mac и откроет браузер. Обычно адрес — `http://localhost:8080`; если этот порт занят при первом запуске, будет выбран свободный порт до 8090.

Готовая сборка включена в архив и Git-ветку. Node.js, npm, Docker и база данных для просмотра не нужны. Открывать `index.php` двойным кликом в браузере не нужно — его обслуживает встроенный сервер PHP. Повторный запуск использует работающий сервер и тот же порт.

Если macOS не разрешает открыть скачанный `.command` двойным кликом, откройте Терминал в распакованной папке и выполните:

```sh
bash tools/native.sh start
```

Чтобы открыть Терминал в папке, можно перетащить её в окно Терминала после ввода `cd `, затем нажать Enter. Не нужно отключать защиту macOS.

Для остановки откройте `Stop GraphOnline.command` или выполните:

```sh
bash tools/native.sh stop
```

Закрытие вкладки браузера не останавливает сервер. Локальные черновики находятся в браузере; опубликованные графы — в `tmp/saved` внутри распакованной папки. Остановка сохраняет данные. Если изменить порт, браузер увидит другой адрес хранилища; нужные графы сначала экспортируйте в файл. При перемещении папки сначала остановите сервер; при переходе на другой способ запуска используйте тот же порт, чтобы сохранить доступ к черновикам.

Если порт сохранённого экземпляра занят другой программой, запустите с явно выбранным портом:

```sh
GRAPHONLINE_PORT=8090 bash tools/native.sh start
```

Логи для диагностики:

```sh
bash tools/native.sh logs
```

Если PHP находится в другом месте, можно выбрать его явно:

```sh
GRAPHONLINE_PHP=/path/to/php bash tools/native.sh start
```

Состояние сервера и лог находятся в `.graphonline-native`, выбранный порт — в `.graphonline-port`. Эти файлы не публикуются в Git. Остановка проверяет, что сохранённый PID принадлежит серверу этой папки.

Docker остаётся необязательным способом запуска. Если он использовался раньше, сначала остановите его сервер, чтобы освободить порт:

```sh
bash tools/local.sh stop
# Запуск через Docker при необходимости:
bash tools/local.sh start
```

Скрипт совместим с синтаксисом Bash 3.2. Работа PHP проверяется непосредственно на Linux-хосте; запуск на физическом Mac пока не проверен. Встроенный PHP-сервер предназначен для локальной работы и слушает только loopback-интерфейс.
